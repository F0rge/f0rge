Overflow strategy

B+ has a label-length budget. Past that budget the control degrades through two tiers rather than truncating or breaking. The component picks the tier from option count + max label length — the consumer doesn't have to choose.

Decision rule
  1. Tier 1 — Compact segmented: all labels ≤ ~10 chars AND ≤ 4 options. Single-line, equal columns, ~44px row.
  2. Tier 2 — Wrapping segmented: any label 11–18 chars (or 2 short words). Same chrome, labels allowed to wrap to 2 lines, row grows to ~56px. Every segment in the row reserves the same height so visual rhythm holds.
  3. Tier 3 — Stacked list: any label > 18 chars OR > 4 options OR a label that would still ellipsis at tier 2. Pattern switches to a vertical stack of full-width buttons with a radio indicator.

Thresholds are tuned for the current card width (~340–420px). They're enforced at the component layer so a future custom tracker with long labels degrades automatically — the consumer can't accidentally create a broken row.

Bowel movement description
Tier 3 · stacked

Labels are sentence fragments. Horizontal layout can't carry them at any reasonable card width without truncation or wrap-juggling. Pattern switches to a vertical radio list — full width per row, generous touch target, radio dot confirms selection (horizontal position no longer signals it).

5+ options also fall to stacked
Tier 3 · count trigger

Five segments at ~70px each = sub-readable text and sub-44px touch on most phones. Cap segmented at 4 options.

In code: ScaleInput gains a single layout?: 'auto' | 'segmented' | 'stacked' prop. Default is auto — at render time it inspects the option count and the longest option.label.length and picks Tier 1 / 2 / 3 by the rules above. Wrap behavior in Tier 2 is just CSS (white-space: normal + grid row auto-height). Tier 3 is a different render branch, not a different component.

Why this beats raising the limit: stretching segmented to handle long labels means smaller font, smaller hit targets, and harder-to-scan rows for the 95% of questions that are short. Tiering keeps the common case fast and gives long-label rows a control that's actually designed for sentence-length options.
