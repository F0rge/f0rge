Health Tracker UI redesign — 4 directions

Today's app is mobile‑first and squeezes the same single‑column form onto desktop and iPhone alike. On phones it feels cramped (tiny ingredient inputs, 6pt edit buttons). On desktop it wastes the space. Below are four responsive redesigns, each with a desktop view and an iPhone view, that treat the two form factors as different surfaces — not the same layout at different widths.

What we're fixing

Three concrete pain points came out of the live UI walkthrough:

Cramped on iPhone

Ingredient editor input ends up ~6pt with text wrapping mid‑word. H‑score badges and × buttons crash together. Hard to tap accurately.

Wasted desktop space

A 32rem column floats in the middle of a 1440px screen with nothing on either side. Insights, history, and inspector panels could live there.

One mental model

The whole day is one giant form. Easy to lose place. No way to peek at correlations or last‑week context while logging.

The four directions

Each link below opens a single mockup page with both desktop (1280) and iPhone (375) views, plus the design rationale. V4 is a remix of V2 and V3.

Direction 1 Notion / Linear flavor

Workspace
split‑pane productivity

Desktop = sidebar · canvas · inspector. The inspector is the punchline — selecting any photo opens a roomy ingredient editor on the right. On mobile, the inspector becomes a 90% bottom sheet with the same big, comfortable inputs.

Ingredient editor finally has space
Power users get keyboard nav (⌘K)
Closest to the current form mental model — easiest migration
Form is still long — no re‑frame, just better packaging

Direction 2 Trello / Notion blocks flavor

Cards Canvas
modular dashboard

The day stops being one form and becomes a set of cards — Food, Wellbeing, Gut, Supplements, Notes — that lay out in a 12‑col masonry on desktop and stack on mobile. Each card has a “focus mode” that opens a full‑screen editor.

Cards can be reordered to match how you log
Hero stats strip surfaces day at a glance
Focus mode on mobile = clean comfortable editing
More tap‑to‑expand = more taps; could feel clicky if overdone
Open mockup
Direction 3 Diary / journal flavor

Daily Log Timeline
event stream + composer

The biggest re‑frame. Stop treating a day as one form. Log meals, supplements, symptoms, mood as separate events in a vertical timeline. Desktop adds a live insights rail that recalculates as you go. Mobile compresses to a feed with a FAB composer.

Matches how the day actually unfolds
Real‑time pattern surfacing while logging
FAB pattern is fast and habit‑forming
Biggest schema implication — needs event timestamps everywhere
Loses the "fill once at end of day" affordance — would need an end‑of‑day rollup

Direction 4 ★ Remix · V2 × V3

Daily Board
cards on a timeline spine

Take V2's rich, scannable cards and lay them out chronologically along V3's timeline. Time‑grouped sections (Morning · Midday · Evening · End of day) give the day shape, while a pinned End of day rollup card preserves the "fill once at night" flow. Hero stats strip + insights rail stay.

Best of both: scannable cards + time narrative
Rollup card means power users + casual users both happy
Three‑lens layout (rail · board · patterns) like Linear
Still needs event timestamps on the schema (like V3)

Recommendation

V4 (Daily Board) is the strongest target. Ship in two phases.

V4 captures the best of both worlds — V2's rich, scannable cards as the unit of interaction, arranged along V3's chronological spine, with the pinned End‑of‑day rollup card keeping the "fill once at night" muscle memory alive. It needs a backend change (event timestamps on entries) but is closer to V2's migration cost than V3's full rewrite.

Phase 1 · ship now

Lift V2's hero stats strip + card grid onto the existing form. Big ingredient editor uses V1's bottom‑sheet on mobile and full‑width card on desktop. No schema change yet — the cards just render today's existing entry fields.

Phase 2 · 2026 Q3

Add event_time + event_type to ingestion. Render the time‑grouped timeline. Wire the FAB compose flow. End‑of‑day rollup card stays — it's a saved query, not a separate model.
